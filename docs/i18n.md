# A second language: Spanish

Built 2026-11-13. Answers open question 15 in `docs/architecture.md` ("English
only for v1: code-side slot extraction is per language") with English and
Spanish, and a shape where a third language is a catalogue, a word table and
test cases.

## Which language

`lib/i18n/locale.ts`, pure. The picker's cookie `hf_locale` (path `/hotels`,
a year), else the first language we speak in `Accept-Language` (by weight,
then order), else English.

- The page (`app/page.tsx`) and `<html lang>` (`app/layout.tsx`) start from it;
  `components/i18n.tsx` holds it on the client (`useLocale()`), and the
  picker in the sidebar sets the cookie, changes the screen at once and reloads
  the search so its server-made words ("close to central Porto") follow.
- Every API route reads it per request: `requestLocale()` in `server/http.ts`.
  It is **not stored on the search** (no schema change). The one edge: a
  message queued behind a running turn is answered by the request already
  running, so a signed-in user typing in two browsers set to two languages
  can get a queued reply in the other one.
- Lines already in the chat stay in the language they were written in; only
  new lines follow a switch. Chat rows are text, written once.

## Where the words are

`lib/i18n/catalogue/en.ts` is the source; `es.ts` is typed `Messages` (typeof
en), so a missing key fails `tsc`. A phrase with grammar is a function
(`nights(n)`, `nearMiss(n, eligible)`); which phrases make a line stays in
one place for every language: `lib/replies.ts` (fixed lines, change lines,
answer templates), `lib/reasonText.ts`, `lib/errors.ts`, `server/onboarding.ts`,
`lib/pennyPick.ts`, `lib/placePick.ts`. Each takes the locale last, English
when left out, so English callers and tests are unchanged.

Money, counts and dates go through `Intl` with the locale's tag (`INTL`):
`120 €` (a no-break space before the sign), `11–13 dic, 2 noches`, `16.206`.
Spanish lines contract "de el" to "del" and write decimals with a comma.

**Guards.** `lib/i18n/catalogueGuard.test.ts`: every English key has an entry
in every other language, of the same kind and arity, filled in, and not left
in English (five entries are the same words on purpose, each with its
reason). Mutation-checked 2026-11-13: a deleted `ui.send`, `ui.book` set to
"Book", and `words.nights` returning English each fail it. `errorCopyGuard`
now checks every language's error copy (mutation: a generic Spanish line fails
it). The agent's claims guard reads Spanish claims ("He reservado", "Tu
reserva está confirmada"); mutation: with `CLAIMS_ES` off, the test fails.

## Chat in Spanish

- **Code-side slots** (`lib/router/slots.ts`, words in `lib/router/lexicon.ts`).
  A message is read in both languages, each by its own patterns, so adding
  Spanish changed no English case (all English tests unchanged and passing).
  Read: price caps ("menos de 120 por noche", "máximo 90 €", "no más de 300 en
  total", "el precio me da igual"), the party ("dos adultos y un niño de 5",
  "2 adultos y 2 niños de 4 y 9 años", "somos cuatro", "solo yo", "mi mujer y
  yo"; children without an age for each are not guessed), nights ("una noche
  más", "quita dos noches"), which hotel ("el segundo", "la opción 3", "la 3ª",
  "el último", a name), hiding the map, staged yes/no ("vale", "de acuerdo",
  "mejor no") and "también"/"además". Cases: `slots.es.test.ts`,
  `route.es.test.ts`.
- "cuarto" is not an ordinal here: it is also "room" ("un cuarto doble"), and
  a wrong target answers about the wrong hotel. "solo" is English for alone
  and Spanish for only: a Spanish count ("solo somos dos") wins.
- **Dates are not extracted by code in either language.** "del 1 al 6 de
  diciembre" and "el próximo viernes" are read by the Haiku intent scan and the
  agent, whose prompts now say the message may be Spanish (with those
  examples). Live cases added, not run.
- **Jev** picks labels we supply; the labels stay English. The tier question
  now says the message may be in English or Spanish. 20 Spanish cases are in
  `server/jev/live.test.ts`; **never run**, so whether Jev settles Spanish as
  well as English is not measured.
- **The agent** writes in `<reply_language>` (English or Spanish), whatever
  language the message is in. 6 live cases in Spanish; **never run**.

## The supplier

LiteAPI takes `language` on `/data/places`, `/data/places/{id}` and
`/data/hotel` (measured on the sandbox 2026-11-13: "Londres, Reino Unido";
"Oporto, Portugal"; Spanish hotel descriptions and notes; facility names stay
English, so amenity matching is unaffected). `getSupplier({ language })`
passes it; rates and the facts list are never asked in another language. A
place picked in Spanish is stored with its Spanish name ("Oporto, Portugal").

## The Vio-parity features (merged 2026-11-13)

Their copy is in the catalogues too: the filter chips and their lines
("Solo 4 estrellas o más", "Se muestran solo …"), the full list and its pager,
saved hotels and the heart, the currency chip (currency names from
`Intl.DisplayNames` in Spanish, the list's English name as the fallback), the
"Mejor precio" rooms stepper, the filter near-miss reasons, the new chat lines
(`fullListLine`, `savedLine`, `savedListLine`, `filtersLine`) and every new
error code, including the Deal Freeze ones. `lib/filters.ts` labels take the
locale. The new extractors read Spanish beside English: "4 estrellas",
"valoración de 8", "apartamentos", "albergue", "casa rural", "enséñamelos
todos" (not "todos los demás").

Still English from those features: the hotel FAQ (in `HotelDetail`), checkout
extras and Deal Freeze on the `/book` page (`Checkout`), the chat lines those
flows write ("Booked:", "Frozen:", "Released:", "Cancelled:"), and the freeze
reminder email.

  and cancelled chat lines in `server/checkout.ts`, the fee fallbacks in
  `server/view.ts`) are still English: other work was changing them at the
  same time. Their keys go in the catalogues the same way.
- Admin pages stay English on purpose.
- The country names in the nationality menu (`lib/countries.ts`) are English.
- The page `<title>` and description (`app/layout.tsx` metadata).
- Supplier text that has no language parameter: board names ("Room Only"),
  room names and the rate's own words.
- Jev and the agent in Spanish are unmeasured (above).

## Adding a language

1. Add the code to `LOCALES` and `LOCALE_NAMES`, its `Intl` tags to `INTL`, its
   English name to `LANGUAGE_NAME_EN` (`lib/i18n/locale.ts`).
2. `lib/i18n/catalogue/<code>.ts` typed `Messages`, registered in
   `lib/i18n/index.ts`. The guard lists what is missing or untranslated.
3. Its number and ordinal words in `lib/router/lexicon.ts`, its patterns beside
   the Spanish ones in `slots.ts`, its cases in `slots.<code>.test.ts`, and its
   yes/no words in `lib/stagedPlan.ts`.
4. Its action claims in `server/agent/guards.ts`.
5. Live cases for Jev and the agent; run them before calling it done.
